BMS 无线通讯说明书

通过 MQTT 协议上传 BMS 与 GPS 数据到网页看板

1. 概述与通讯流程

本系统通过 MQTT 协议将底层 BMS 与 GPS 数据实时上传并同步渲染至网页看板。基本环境参数与网络交互架构定义如下：

项目 值 用途
模块串口 115200 / 8 / N / 1，CRLF 默认 AT 指令模式，命令末尾使用 \r\n。 [cite: 4]
BMS 服务器公网地址 http://8.148.13.100:8080/ 网页看板地址 [cite: 4]
MQTT Broker 8.148.13.100:1883 CT511N 从公网连接该地址；服务器本机 FastAPI 可用 127.0.0.1。 [cite: 4]
上传 Topic bms/data BMS、GPS、telemetry 数据发布到这里，FastAPI 订阅并更新网页。 [cite: 4]
控制 Topic bms/control 网页按钮下发控制命令；CT511N/MCU 必须订阅这个 topic。 [cite: 4]
*注意：串口参数、服务器公网 IP 以及各端口可相应改变 [cite: 5]

通讯交互数据流向：

➔ 点击网页按钮 [cite: 7]
➔ FastAPI POST /api/control/bms 或 /api/control/gps [cite: 8]
➔ MQTT publish 到 bms/control [cite: 9]
➔ CT511N/MCU 订阅 bms/control [cite: 10]
➔ MCU 解析 payload 并执行：REQ_BMS 或 AT+GPSSTEX [cite: 11]
➔ MCU/CT511N publish 数据到 bms/data [cite: 12]
➔ FastAPI 订阅 bms/data，网页刷新 [cite: 13]

2. 防止卡死恢复机制

建议每次调试开始前先清理旧 MQTT/IP 会话，避免上一次连接残留导致 MIPSTART、MCONNECT 或订阅失败。环境异常或卡死时也应优先执行本章指令： [cite: 23]

清理控制指令 用途说明
AT+MDISCONNECT 挂断 MQTT 会话连接。 [cite: 24]
AT+MIPCLOSE 关闭 socket 端口。 [cite: 24]
*说明：如果模块提示当前没有 MQTT/IP 会话，返回 ERROR 或类似提示不一定是问题。目标是把旧连接清掉。如果仍然异常，再执行模块复位或重新打开网络，具体命令以手册和固件返回为准。 [cite: 25]

3. 模块联网步骤指令

指令序号 串口发送 期望返回 / 说明
3.1 AT 返回 OK，说明串口可用。 [cite: 27]
3.2 AT+QICSGP=1,1,"","","" 配置 APN。该联网卡可先空参数测试。 [cite: 27]
3.3 AT+NETOPEN 返回 OK 与 +NETOPEN:SUCCESS 表示数据网络打开。 [cite: 27]
3.4 AT+CEREG? 第二位为 1 或 5 通常表示已注册网络；若反复为 2/3，先检查 SIM、天线、信号和流量。 [cite: 27]
3.5 AT+CEREG=0 关闭网络注册状态的主动上报。 [cite: 27]

4. 连接MQTT Broker并订阅控制Topic

指令序号 串口发送 期望返回 / 说明
4.1 AT+MCONFIG="BMS_0001" 设置 MQTT Client ID。不同设备必须使用不同 ID，避免互相踢线。 [cite: 29]
4.2 AT+MIPSTART="8.148.13.100",1883 连接 MQTT Broker。成功通常返回 +MIPSTART: SUCCESS。 [cite: 29]
4.3 AT+MCONNECT=1,60 连接 MQTT 会话。成功通常返回 +MCONNECT: SUCCESS。 [cite: 29]
4.4 AT+MSUB="bms/control",0 订阅网页控制 Topic。没有这一步，网页按钮发出的控制消息不会下发到 CT511N/MCU。 [cite: 29]
*说明：若要让网页按钮控制设备，订阅控制 topic 是必须的。 [cite: 30]

5. 网页按钮与下位机动作约定

网页按钮 MQTT Topic Payload MCU/串口桥接程序动作
更新 BMS 数据 bms/control REQ_BMS_UPDATE MCU 读取 BMS 状态，组包 JSON 后发布到 bms/data。 [cite: 33]
更新 GPS 定位 bms/control AT+GPSSTEX MCU 收到后向 CT511N 串口发送 AT+GPSSTEX，读取返回的 +GPSSTEX，再发布到 bms/data。 [cite: 33]

6. 数据上报规范 (JSON/原始行)

6.1 上传 BMS 数据（JSON 版）

网页左侧会显示 voltage、current、soc、temperature 等字段。代码会把 type=bms 之外的字段作为 BMS 指标渲染。 [cite: 47]

AT+MPUB="bms/data",0,0,"{\"type\":\"bms\",\"voltage\":52.3,\"current\":1.8,\"soc\":76,\"temperature\":31.5}" [cite: 44]
成功后返回：
OK
+MPUB:SUCCESS [cite: 46]

6.2 上传 GPS 定位 (JSON 版)

网页右侧会显示经纬度、海拔、速度、卫星数；地图会移动到该坐标。 [cite: 61]

AT+MPUB="bms/data",0,0,"{\"type\":\"gps\",\"fix_status\":1,\"longitude\":114.394170,\"latitude\":30.515838,\"high\":15.598,\"speed\":0.466,\"satellites\":19}" [cite: 60]

6.3 上传 BMS + GPS 合并数据 (JSON 版)

使用 telemetry 类型，一条消息同时带 BMS 和 GPS： [cite: 63]

AT+MPUB="bms/data",0,0,"{\"type\":\"telemetry\",\"bms\":{\"voltage\":52.3,\"current\":1.8,\"soc\":76,\"temperature\":31.5},\"gps\":{\"fix_status\":1,\"longitude\":114.394170,\"latitude\":30.515838,\"high\":15.598,\"speed\":0.466,\"satellites\":19}}" [cite: 64]

6.4 上传 GPS 定位 (原始行)

代码也能解析 +GPSSTEX / +GPS5TEX 形式的原始 GPS 行，可直接发布： [cite: 66]

AT+MPUB="bms/data",0,0,"+GPSSTEX: 1, 1, 114.394170, 15.598000, 30.515838, 0.466000, 28, 19" [cite: 69]

7. GPS 硬件、有源天线与 AGNSS 启动流程

说明：如果底板使用有源 GPS 天线，需要先打开天线偏置供电。若使用无源天线或底板供电方式不同，必须按硬件设计和手册确认后再执行偏置供电相关命令。 [cite: 72]
指令序号 串口发送 用途
7.1 AT+CGDRT=12,1 打开指定通道的偏置供电开关，有源天线必须。 [cite: 73]
7.2 AT+CGSETV=12,1 设置天线供电电压/使能状态，具体含义以手册 5.7.1 为准。 [cite: 73]
7.3 AT+CGGETV=12 确认天线供电状态。 [cite: 73]
7.4 AT+MGPSC=1 启动 GPS/GNSS 核心硬件引擎。 [cite: 73]
7.5 AT+AGNSSGET=pos.asrmicro.com 通过 4G 下载 AGNSS 辅助星历数据。 [cite: 73]
7.6 AT+AGNSSSET 将已下载的 AGNSS 数据写入/喂给 GNSS 芯片。 [cite: 73]
7.7 AT+GPSMODE=1 设置 GPS 模式为热启动，利用星历和时钟缓存加速定位。 [cite: 73]
7.8 AT+GPSSTEX 请求输出扩展定位结果，返回后可发布到 bms/data。 [cite: 73]
说明：AGNSS 依赖 4G 网络、DNS、服务器可达性和模块固件支持。若 AGNSSGET 失败，不一定代表 GPS 硬件坏了；可以先测试普通冷启动/开阔天空定位。 [cite: 74]

其它设置：

  • AT+MGPSGET=ALL,0 ：关闭 GPS 串口刷屏 [cite: 76]
  • AT+MGPSGET=ALL,1 ：开启 GPS 串口刷屏 [cite: 76]

9. 快速排错

网页按钮点了，串口没反应
是否执行 AT+MSUB="bms/control",0；FastAPI 是否真的 publish 到 bms/control；MCU 是否解析下行 MQTT payload。 [cite: 89]
mosquitto_sub 能看到 bms/control，但 CT511N 串口没显示
CT511N 没订阅、订阅失败、Client ID 冲突、连接断开，或 Broker 地址不一致。 [cite: 89]
CT511N 串口收到 payload，但 GPS 没输出
payload 只是 MQTT 下行消息，不会自动当 AT 执行；MCU 需要把 AT+GPSSTEX 重新写入 CT511N 串口。 [cite: 89]
MQTT 连接卡住
先 AT+MDISCONNECT，再 AT+MIPCLOSE，然后重新 MIPSTART/MCONNECT/MSUB。 [cite: 89]
GPS 长期未定位
检查天线、是否开阔天空、有源天线偏置供电、MGPSC、AGNSSGET/SET、GPSMODE。 [cite: 89]
